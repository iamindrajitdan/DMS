================================================================================
Next-Generation, AI-Native ECM SaaS Platform
Volume 5 & 6: Technical Architecture & Technology Decision Book
================================================================================

1. API Gateway & Ingress: Traefik / Kong
- Technology: Traefik (Primary for Local/K8s) or Kong.
- Rationale: Traefik offers dynamic routing with zero-configuration auto-discovery for Docker Compose and Kubernetes. It seamlessly handles TLS termination, rate limiting, and routing traffic to appropriate microservices based on path or headers. This is critical for local development where microservices scale up/down dynamically.

2. Compute & Microservices: Python & Go (Antigravity Architecture)
- Technology: Python (FastAPI) & Go (Fiber/Gin).
- Rationale: 
  * Python/FastAPI handles the "Brain" operations: AI orchestration, LLM interfacing, semantic chunking, prompt engineering, and complex metadata extraction. Python is the de-facto standard for AI ecosystems.
  * Go handles the "Brawn": high-throughput event streaming, rapid binary file I/O (upload/download), and concurrency-heavy tasks. Go's goroutines ensure effortless scalability and fast execution, providing a lightweight footprint ideal for a microservice mesh.

3. Metadata Engine & Graph: PostgreSQL + pgvector / Neo4j
- Technology: PostgreSQL (with pgvector) & Neo4j.
- Rationale: M-Files thrives on "What it is, not where it is." We use PostgreSQL for robust relational mapping, strict ACID compliance, and fine-grained ACLs (Access Control Lists). We extend this with Neo4j to model complex ontological relationships (e.g., "Contract A is linked to Vendor B and Employee C"), allowing us to beat legacy metadata engines by traversing complex document graphs in milliseconds.

4. Search & Vector Engine: OpenSearch & Qdrant
- Technology: OpenSearch (Lexical) + Qdrant (Semantic).
- Rationale: To provide a true AI-native search experience, we require hybrid search. OpenSearch provides ultra-fast traditional keyword/lexical search (BM25). Qdrant serves as the dedicated vector database, storing high-dimensional embeddings generated by the AI layer. This allows users to search by meaning and context ("Show me all employment contracts signed last quarter involving non-compete clauses").

5. Event Bus & State Machine: Kafka & Temporal
- Technology: Apache Kafka & Temporal.io.
- Rationale: In an enterprise ECM, documents undergo complex lifecycles (Ingestion -> Virus Scan -> OCR -> AI Extraction -> Approval Workflow). Kafka acts as the high-throughput, fault-tolerant event mesh decoupling these steps. Temporal acts as the state machine/orchestrator, ensuring that if a microservice crashes during a 5-step document approval workflow, the state is preserved and automatically retries, guaranteeing resilient enterprise workflow execution.

6. Storage Layer: MinIO
- Technology: MinIO.
- Rationale: MinIO provides an S3-compatible, high-performance local object storage layer. For local development, it perfectly mimics AWS S3, ensuring that binary blobs (PDFs, videos, images) are stored efficiently. It supports object lock (immutability for compliance) and bucket versioning, essential for a modern ECM.

7. Containerization & Orchestration: Docker Compose & Kubernetes
- Technology: Docker Compose (Local Dev) & Kubernetes (Skaffold/Helm).
- Rationale: 
  * Docker Compose is used for the immediate, fully functional local development blueprint, spinning up the DBs, MinIO, Kafka, and microservices with a single `docker-compose up` command.
  * Kubernetes (using Helm for templating and Skaffold for continuous local deployment) provides the orchestration pathway to production, ensuring the modular "Antigravity" architecture can seamlessly transition from a developer's laptop to an enterprise cloud cluster.
