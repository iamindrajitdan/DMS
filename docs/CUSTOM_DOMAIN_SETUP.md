# Custom Domain Setup and Production Launch Guide

This guide details the procedure for connecting a custom domain to NextGen DMS, automating TLS/SSL certificates, and fulfilling all pre-launch enterprise compliance requirements.

---

## Pre-Launch Verification Checklist

Before releasing NextGen DMS into production, verify that each milestone below is satisfied:

- [x] **No Vibe-Coded Aesthetics**: Zero purple gradients, zero pill-shaped buttons, zero fake reviews, zero fake metrics, zero vague hero text.
- [x] **No Emoji Icons or Em-Dashes**: Strictly professional SVG iconography and clean punctuation.
- [x] **No AI Watermarks**: Default "Generated by create next app" and AI templates removed.
- [x] **Custom Favicon Active**: SVG and ICO favicons deployed at `/favicon.svg` and `icon.svg`.
- [x] **Privacy Policy Live**: Published at `/privacy` covering data isolation, S3 storage, and retention.
- [x] **Terms and Conditions Live**: Published at `/terms` guaranteeing 100% customer document ownership.
- [ ] **Custom Domain Connected**: Point DNS A/CNAME records and bind TLS reverse proxy.

## 1. DNS Record Configuration

Configure DNS records with your registrar or DNS provider (e.g., Cloudflare, Route 53, Namecheap):

| Record Type | Host / Name | Target / Value | TTL | Note |
| :--- | :--- | :--- | :--- | :--- |
| **A** | `dms` (or `@` for root) | `YOUR_SERVER_PUBLIC_IP` | 300 / Auto | Points subdomain to host |
| **CNAME** | `api.dms` (optional) | `dms.yourdomain.com` | 300 / Auto | If using dedicated API host |

Verify DNS propagation:
```bash
dig +short A dms.yourdomain.com
```

## 2. Reverse Proxy and Automated SSL Setup

In production, NextGen DMS runs behind a reverse proxy that terminates TLS (HTTPS) on port 443 and forwards traffic to the internal containers (`apps/web` on port 3000, `apps/api` on port 3001).

### Option A: Caddy (Recommended for Zero-Touch HTTPS)

Caddy automatically provisions and renews Let's Encrypt / ZeroSSL certificates:

```caddy
# /etc/caddy/Caddyfile

dms.yourdomain.com {
    # Security Headers
    header {
        X-Content-Type-Options "nosniff"
        X-Frame-Options "DENY"
        Referrer-Policy "strict-origin-when-cross-origin"
        Strict-Transport-Security "max-age=31536000; includeSubDomains"
    }

    # Route API requests to NestJS
    handle /api/* {
        reverse_proxy localhost:3001
    }

    # Route web application to Next.js
    handle {
        reverse_proxy localhost:3000
    }
}
```

Reload Caddy:
```bash
sudo systemctl reload caddy
```

---

### Option B: Nginx with Certbot

```nginx
# /etc/nginx/sites-available/dms.yourdomain.com.conf

server {
    server_name dms.yourdomain.com;

    location /api/ {
        proxy_pass http://127.0.0.1:3001;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

Obtain TLS certificate via Certbot:
```bash
sudo certbot --nginx -d dms.yourdomain.com
```

## 3. Environment Variable Binding

Update `.env` in the root workspace and `apps/web`:

```env
# Custom Domain Configuration
NEXT_PUBLIC_APP_URL=https://dms.yourdomain.com
NEXT_PUBLIC_API_URL=https://dms.yourdomain.com/api/v1
```

Rebuild and start containers:
```bash
docker compose up -d --build
```
